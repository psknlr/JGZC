## 共享事实空间

`osteosarc_agent/guidelines/facts.py` 声明全部 122 个事实，每个带标签、单位、分组与来源层：

| 来源层 | 谁写 | 例子 |
| --- | --- | --- |
| `intake` | 从病历读入 | `age`、`grip_kg`、`egfr` |
| `derived` | 结构化 Agent 推导 | `bmi`、`asmi`、`tscore_min`、`hypocalcemia`、`frid_count` |
| `agent` | 后续 Agent 回写 | `dx_osteoporosis`、`fall_risk_tier`、`very_high_fracture_risk` |

**回写是这条流水线成立的关键**。因为诊断与风险的结论会写回同一个命名空间，语料里可以直接写

```json
{"fact": "very_high_fracture_risk", "op": "is_true"}
```

而不必在每条推荐里重新推导一遍"什么算极高风险"。代价是顺序变成硬依赖，所以顺序写死在
`Orchestrator.pipeline` 里，而不是让模型自由编排。

事实词表同时是**语料的校验表**：装载时逐一比对谓词引用的 `fact`，未声明即拒绝装载。
拼错的事实名不会变成"永远无法判定的条件"，而是一次响亮的启动失败。

## 子智能体契约

每个子智能体是 `RunState → payload`，由 `SubAgent.__call__` 包住，提供三条不可绕过的保证：

1. **输出按 schema 校验**（`osteosarc_agent/schemas.py`）。不合格的 payload 被丢弃，
   该 Agent 记为 `blocked` 并附上问题清单，而不是把畸形数据传给下游。
2. **失败被隔离**。抛异常只让这一个 Agent 降级并被记录，不会中断整次运行；但它的沉默
   **绝不会被读成"未见异常"**——控制台会明确显示"该 Agent 未能完成"。
3. **事实回写是显式的**。Agent 通过 `derived_facts(payload)` 返回要写入共享空间的事实，
   写入结果记在该 Agent 的 `notes` 里，不是埋在函数体里的副作用。

`schemas.py` 里有一处内容级校验值得单独说：`SafetyAndFollowup` 要求 `checks_run` 包含
全部七项安全检查，且随访必须有 m3/m6/m12。缺项直接拒收——**一份有静默缺口的安全报告
比没有报告更危险**，因为它看起来是完整的。

## 证据台账

`osteosarc_agent/state.py` 的 `EvidenceLedger` 按首次引用顺序分配 `E01`、`E02`…，
一个 `rec_id` 只占一个编号。任何结论、方案卡片、冲突立场都携带它依赖的编号，
编号解析回：指南条目 + 出处 + **适用性推演树**。

台账保存的是"被排除"的条目，和"适用"的条目一样多——因为
"eGFR 32 把双膦酸盐拿下桌面"是一个发现，不是一个缺席。

## 状态语义

| 状态 | 含义 | 退出码 |
| --- | --- | --- |
| `ok` | 六个 Agent 全部完成，无阻断性安全问题 | 0 |
| `needs_action` | 存在阻断性安全问题，药物部分不得下达 | 2 |
| `degraded` | 有 Agent 未完成，结论不完整 | 3 |

## 确定性

同一份病例 + 同一份语料 → 同一份决策。没有随机性、没有并发合并顺序问题、
没有时间依赖。证据编号取决于语料顺序与引用顺序，不取决于哪个 Agent 先跑完。
测试 `test_rerunning_a_case_is_deterministic` 守住这条。

## 认知层的位置

模型（如果配置了）只在最后被调用一次，输入是**已经确定的结论**，输出是两段文字，
并且要通过剂量扫描、药名白名单与放行式表述检查。它不选推荐、不消解冲突、
不放行安全门、不生成剂量。见 [LIMITATIONS.md](LIMITATIONS.md) 与
`osteosarc_agent/llm/narrate.py`。
