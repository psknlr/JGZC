# 控制台

```bash
python -m osteosarc_agent ui --port 8000
python -m osteosarc_agent ui --corpus /srv/licensed-corpus/ --llm anthropic
```

标准库 HTTP 服务 + 一个自包含页面：没有框架、没有 CDN、没有构建步骤，
在没有外网的院内网络与 notebook 里都能跑。默认只绑定 `127.0.0.1`——
这是一个没有认证的本地工具，要暴露到共享网络请自行放一层认证代理在前面。

## 证据抽屉

点任意「查看循证依据」或证据编号（`E07`），右侧滑出抽屉，显示：

* 条目状态徽章：**本例适用 / 本例已排除 / 本例不适用 / 数据不足**；
* 指南名称、发布机构、年份、地区、证据体系、推荐强度、证据等级；
* 推荐正文与"为什么重要"；
* **适用性推演树**——这是抽屉的核心，不是指南原句，而是哪几条**本患者的事实**
  让这条推荐成立，逐个节点标注 ✓ / ✗ / ?：

```
✓ 全部满足
   ✓ 骨质疏松诊断成立 — dx_osteoporosis=True
   ✓ eGFR < 35 — egfr=32 < 35
```

* 若有排除条件，另附排除推演树；
* 若因缺数据无法判定，列出缺失的事实。

## 未评估轴的画法

雷达图上置信度过低的轴画成**空心虚线点**并标注"未评估"，不参与多边形填充。
把没做的检查渲染成一块令人安心的绿色，是这张图能犯的最危险的错误。

## 端点

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/` | 控制台页面 |
| GET | `/api/cases` | 示例病例、语料统计、Agent 目录 |
| GET | `/api/assess?case=demo` | 跑一个示例病例 |
| POST | `/api/assess` | `{"case": "demo"}` 或 `{"record": {...}}` |
| GET | `/api/corpus` | 语料统计 |
| GET | `/api/guideline/<rec_id>` | 单条推荐的完整定义（含谓词） |

POST 的病例记录**只在请求生命周期内存在**，不落盘——病例记录是临床数据。

## 主题

跟随系统深浅色（`prefers-color-scheme`）。所有插值都经过转义，
病例文本不会变成页面里的标记。
