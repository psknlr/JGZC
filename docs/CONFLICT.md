# 指南冲突消解

五部指南对一位患者的输出不是五段文字，而是**每个临床问题一个判读**。

## 六种判读

| 判读 | 何时给出 |
| --- | --- |
| **一致推荐** `consensus` | 适用条目方向一致，且强度为强推荐/共识 |
| **条件推荐** `conditional` | 方向一致，但含有条件推荐、专家意见或 `consider` |
| **存在争议** `disputed` | 真分歧（见下） |
| **不适用于本患者** `not_applicable` | 该问题下条目全部被排除或适用条件不成立 |
| **争议已被本例事实消解** `resolved_by_patient` | 指南间本有分歧，但本例事实拿掉了一方 |
| **数据不足，无法判定** `insufficient_data` | 关键事实缺失，适用性无法判定 |

前四类是产品面向用户的主判读；后两类是数据逼出来的，把它们折进前四类都是撒谎：

* 把 `resolved_by_patient` 报成"一致推荐"，会掩盖**答案依赖于一个化验值**——
  换个 eGFR，答案就变了，医师有权知道这一点；报成"存在争议"，则把病历已经做出的决定
  又推回给医师。
* 把 `insufficient_data` 报成"不适用"，等于把没测的项目当成阴性结果。

## 什么算真分歧

分两种，都在**适用于本患者**的条目之间判定：

**方向冲突**：同一个 `action` 上同时出现正向（`recommend/require/consider`）
与负向（`avoid/against`）推荐。

**互斥问题上的不同答案**：问题在目录中标注了 `exclusive: true`，而适用条目给出了
两个以上不同的正向 `action`。

`exclusive` 这个标注是整套算法的支点：

| 问题 | 三个不同 action | 是分歧吗 |
| --- | --- | --- |
| 增加跌倒风险的药物如何处理 | 减停 FRIDs / 避免苯二氮䓬 / 降低抗胆碱负荷 | 否，互补 |
| 极高骨折风险者的初始药物选择 | 促骨形成起始 / 双膦酸盐一线 | 是，互斥 |

没有这个区分，冲突检测要么对每个多来源话题狼来了，要么漏掉真正要紧的分歧。

### 蕴含关系

`subsumes` 处理嵌套目标：「1.2～1.5 g/kg」蕴含「至少 1.0 g/kg」，
所以在计数不同答案之前，被蕴含的动作会先被去掉。否则每一组"更严格的版本 + 基线版本"
都会被误报成分歧——`gc_male` 病例正是靠这一条把蛋白目标从"存在争议"降级为可执行的一致意见。

## 消解：先看患者，再看指南

判定分两遍：

* **潜在分歧**：对该问题下的**全部**条目计算（不管它们是否适用于本例）；
* **现实分歧**：只对**适用于本例**的条目计算。

于是：

```
现实分歧成立            → 存在争议
现实无分歧、潜在有分歧   → 争议已被本例事实消解
两者都无分歧            → 一致推荐 / 条件推荐
无适用条目              → 不适用 / 数据不足
```

消解时会列出**被拿掉的立场**及其原因，原因有两种来源：

* **禁忌/排除**：`excluded_when` 的真值叶子，例如 `eGFR < 35（egfr=32 < 35）`；
* **适用条件不成立**：`applies_when` 的假值叶子，例如
  `近12个月内骨折（fracture_within_12m=False）`、`绝经后（postmenopausal=False）`。

参考病例的实际输出：

```
【争议已被本例事实消解】极高骨折风险者的初始药物选择：促骨形成起始还是双膦酸盐一线
  ✖ 去除「start_bisphosphonate」（原发性骨质疏松症药物治疗指南）：eGFR < 35（egfr=32 < 35）
  ✖ 去除「prefer_potent_agent_imminent_risk」（骨质疏松性骨折诊疗指南）：
      适用条件不成立：近12个月内骨折（fracture_within_12m=False）
  保留 ['start_anabolic_first']
```

## 争议存活时，平台不选边

`decision_support` 给出三样东西，都不是结论：

1. 一句明确的立场声明——本平台不对存在争议的问题替医师做选择；
2. 本例可用于权衡的患者特异性因素（肾功能、年龄、T 值、近期骨折、心血管事件、
   跌倒风险、肌少症、低钙、多重用药、依从性……）及其取值；
3. 下一步：由主管医师结合可及性、患者偏好与共病负担决定，并把理由写入病历。

## 平台策略

对少数问题，平台有一个**持有分歧的方式**，写在 `PLATFORM_POLICY` 里并显示在争议卡片上。
它不选赢家，只说明这套系统怎么在不牺牲任何一方的情况下继续往前走：

| 问题 | 平台策略 |
| --- | --- |
| 肌少症采用哪套诊断标准与切点 | 三套全部判定并列呈现；中国人群部署下以 AWGS 为主判定并标注该选择 |
| 没有肌量测定能否诊断并开始干预 | 按 AWGS/EWGSOP2 的"可能肌少症"立即干预，同时按 GLIS 标注"不能确诊"，并把补测 ASMI 列入即刻随访 |
| 每日蛋白质摄入目标 | 不输出单一数字，转为要求肾脏科与营养科共同设定并动态监测 |
| 极高骨折风险者的初始药物选择：促骨形成起始还是双膦酸盐一线 | 列出双方立场与本例决定性因素，由医师决定并记入病历 |
| 从多大年龄开始筛查骨密度 | 按本机构所在地区的指南执行，并在报告中注明所依据的筛查年龄标准 |

只报"存在争议"然后停下，是把工作推回给读者。在存在可辩护的持有方式时说出来，
是分析与耸肩的区别。

## 中西医的处理

中医条目与现代医学条目在同一套机制里判定，但**证据体系差异不等于反对意见**。
当某个问题下只有中医指南作出推荐时，输出会明确写：

> 该问题下仅中医指南作出推荐，现代医学指南未涉及——这是证据体系与关注问题不同，
> 不等于现代医学指南持反对意见。

同时，中医推荐里"不能替代具有抗骨折证据的抗骨质疏松药物"这类**定位性约束**
以 `direction: require` 编码，会作为硬约束进入方案层与安全层。
